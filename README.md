# gaudi2-qwen3.6-27b

Build recipes for serving Qwen3.6-27B-FP8 on Intel Gaudi 2 with vLLM and the vllm-gaudi plugin. The repo is a set of `.env` config files, one per experiment. Hardware: 8x Gaudi 2 HL-225 (96 GB each).

Model weights are not included. Set `MODEL_PATH` to your own copy of `Qwen3.6-27B-FP8`.

## Status

Secondary / reference model. The champion config is `configs/qwen36-27b.env`. The comments in the other files call it the "base champion" and the "deployed base champion", and the MTP file states "champion = base". Other configs are single-variable experiments against it.

Champion settings (from `configs/qwen36-27b.env`):

| Setting | Value |
|---|---|
| Image | `vllm-gaudi:next` |
| Served model name | `qwen36-27b` |
| Tensor parallel size | 8 |
| Quantization | `--quantization fp8` |
| KV cache dtype | `fp8_inc` |
| `--max-model-len` | 2048 |
| `--max-num-seqs` | 64 |
| `--gpu-memory-utilization` | 0.04 (very low, so it can share cards with another model) |
| `--block-size` | 128 |
| Scheduling | `--async-scheduling` |
| Prefix caching | off (`--no-enable-prefix-caching`) |
| Mode | eager (`PT_HPU_LAZY_MODE=0`), `VLLM_SKIP_WARMUP=true` |

## Quick start

The configs are inputs to the shared launchers in [gaudi2-common](https://github.com/LiquidLava1990/gaudi2-common) (`serve.sh`, `containers.sh`). A config sets these shell variables for the launcher: `IMAGE`, `MODEL_PATH`, `SERVED_NAME`, `MODEL_ENV` (extra container `-e` flags) and `VLLM_ARGS` (vLLM server arguments). Some files also set `EXTRA_MOUNTS`, `PORT` or `SERVE_LAYOUT`.

1. Clone both repos.
2. Put your weights where the launcher expects `MODEL_PATH`.
3. Pass `configs/qwen36-27b.env` to the launcher from gaudi2-common.

The exact command is defined in the gaudi2-common README, not in this repo. The config comments say each config key gets its own container and compile cache.

## Results

Only numbers reported in `configs/qwen36-27b.env` and `configs/qwen36-27b-conc.env`, which has the same settings as the champion. Test conditions are not fully described in the files.

| Item | Value |
|---|---|
| Memory per card at util 0.04 | 7.3 GB |
| Decode throughput, 16 concurrent | 394 tok/s |
| Decode throughput, 32 concurrent | 733 tok/s |
| Decode throughput, 64 concurrent | 1265 tok/s (19 tok/s per user) |
| 64 concurrent requests | 64/64 ok, no KV starvation reported |
| KV pool at util 0.04 | 474 blocks, 60,672 token slots |
| Single-stream figure, eager base | 33.1 (unit not stated in the files) |

A larger 46 GB pool gave 390 (c16) and 716 (c32) decode tok/s, so the comments conclude the bigger pool added nothing.

## Other configs

All in `configs/`. Each differs from the champion as listed.

| File | What it changes |
|---|---|
| `qwen36-27b-conc.env` | Same settings as the champion, used to measure concurrency up to 64. |
| `qwen36-27b-dynshapes.env` | Adds `VLLM_T_COMPILE_DYNAMIC_SHAPES=false` and uses `--max-num-seqs 16`. Comments report 39.1 single-stream (+18%) but jittery under concurrency. |
| `qwen36-27b-coresident.env` | Port 8001, prefix caching on. A comment marks it "PRODUCTION 2026-07-06": util 0.85, `--max-model-len 262144`, `--max-num-seqs 128`. No results are recorded for it. |
| `qwen36-27b-gdnthread.env` | Sets `QWEN_GDN_THREAD_META=1` and mounts a patched `vllm_gaudi` tree (not in this repo) to fuse each decoder layer into one graph. No result recorded. |
| `qwen36-27b-graph.env` | Lazy mode with lazy collectives and `--enforce-eager`, util 0.10. No result recorded. |
| `qwen36-27b-lazy.env` | Lazy mode with lazy collectives, util 0.10. Speed test, no result recorded. |
| `qwen36-27b-int4kv.env` | `--kv-cache-dtype turboquant_k8v4` instead of `fp8_inc`. No result recorded. |
| `qwen36-27b-mtp.env` | Native MTP via `--speculative-config`. Blocked: fails on the first prefill (block table cannot hold the hybrid multi-group layout). |
| `qwen36-27b-prof.env` | Static shapes plus the torch profiler, util 0.10. |
| `qwen36-27b-tp2.env` | TP2 on 2 cards, util 0.25, static shapes. No result recorded. |
| `qwen36-auto.env` | Generated by an autoconfig script: `dp8_tp1` layout, `--max-model-len 131072`, tool-call and reasoning parsers. Its comments claim +33% C1 decode and +60% C64 throughput versus TP8. |

`configs/qwen36.env` is a different model (Qwen3.6-35B-A3B, MoE, bf16) and is not part of this recipe.

## Notes

- Memory is dominated by the GatedDeltaNet (Mamba-style) state pool, not the attention KV cache. The pool is sized by `--gpu-memory-utilization`, so the comments treat `--max-num-seqs` as free concurrency.
- 48 of 64 layers are linear attention and 16 are full attention. Mamba/GDN parameters stay in bf16; the comments say quantizing them produced NaNs on a larger sibling model.
- Eager mode is the working path. Lazy mode failed during warmup graph compilation (`synStatus 26`) before `VLLM_SKIP_WARMUP=true` was set.
- The champion's comments say two models switch on the box rather than run together in the production setting, because Gaudi cannot co-tenant TP8 jobs. The util 0.04 setting was sized to share cards.
- Configs that mount a patched `vllm_gaudi` use a local path under `$HOME`. Adjust `EXTRA_MOUNTS` to your checkout.
